## Five remaining engineering risks and implementation order

1. **Acceptance is not yet tied to one immutable end-to-end revision.** The live
   run used in-run corrections. Publish this work, require final Linux/Windows
   CI, then add an aggregate run report containing code revision, profile and
   artifact hashes plus every stage outcome. Independently review private
   audits before declaring complete acceptance. A future approved clean build
   and restart/persistence exercise are still required.
2. **Partial failure has no safe resume protocol.** Creation refuses existing
   paths; first-install playbooks reject existing/mixed state. Implement a
   read-only continuation planner with stage pre/postconditions and exact VM
   bindings first. Add fault-injection tests before any narrowly approved
   resume action. Never infer that a completion flag permits replaying init or
   deleting partial state. Worker replacement and rollback remain separate work.
3. **Configuration is duplicated across layers.** Python, PowerShell, guest
   seed and rendered legacy playbooks carry coupled constants. Two live defects
   involved scope/CIDR assumptions. Introduce one validated versioned profile
   and contract tests covering provisioner -> KVP -> trust -> inventory -> CNI
   -> acceptance. Keep existing disposable and sandbox scopes isolated.
4. **Boot diagnostics and retry classification are incomplete.** The KVP loop
   catches all errors, including permanent identity/scope failures. Introduce
   explicit transient/fatal error codes, elapsed-time deadlines and structured
   progress. Design pre-trust console/serial diagnostics without trusting an
   unverified SSH connection or depending solely on the KVP service under test.
5. **Artifact selection still relies on copied arguments.** The operator
   explicitly requested removal of repeated image path/SHA arguments. Resolve
   approved image and Flannel pins from a reviewed catalog/lock selected by
   profile; validate hashes on every use and show resolved pins in PLAN. Never
   silently use latest or approve the hash of an arbitrary downloaded file.
   Preserve the distinction between checksum integrity and signed provenance.

Recommended next feature PR: profile-based reviewed artifact selection with
offline tests, followed by the continuation planner and structured evidence.
None of these steps require deleting the successful fresh cluster.
